# Reference performance and memory

For the latest recorded acceptance status and unresolved failures, see [release readiness](../RELEASE-READINESS.md) and [known issues](../KNOW-ISSUES.md). Local results below do not establish hosted CI success.

The corrected local acceptance later passed the preview gate; the latest recorded hosted run stopped at Next playback before reaching that benchmark. Historical preview intermittency remains unexplained. The reference visible run measured 1.90 ms for the complete player RAF callback that evaluates and draws a changed frame, with zero dropped frames during three complete 20-second plays. Two earlier full acceptance attempts failed in their third play: first three skipped frames alongside a 160.2 ms in-play RAF gap, then a 30-second timeout. The isolated reproduction passed without changing the timeout or zero-drop criterion. The cause is not established; the isolated PASS did not resolve the intermittency or replace those failed matrices. Evidence is retained under artifacts/ci/failed-preview, artifacts/ci/timeout-preview and artifacts/ci/preview-diagnosis.json. These are measured results for the illustrated short on the host below, not a platform-wide performance promise.

Measured on 2026-10-10 in Lima (reports use UTC): iMac20,1, Intel Core i5-10400F 2.90 GHz, six physical/twelve logical cores, 24 GiB RAM, macOS 15.7.7 (Darwin 24.6.0), Node 24.21.0, Chromium 156.0.8078.4, Playwright 1.64.0, esbuild 0.28.2 and FFmpeg 8.0.1. Run the existing build before benchmarking changed package sources, then:

```sh
node scripts/benchmark-preview.mjs
node scripts/benchmark-export-memory.mjs
node scripts/benchmark-web-memory.mjs

```

The web memory benchmark consumes the verified repetition generated by the Node memory benchmark. Neither script modifies the original fixture or assets. ## Full pipeline memory and export

`ps` RSS is sampled every 250 ms for exports and 500 ms for preview. The local `ps(1)` manual defines RSS in 1024-byte units. Reports sum the benchmark coordinator and all its descendants, excluding the sampling process. Node export includes Chromium/GPU/renderers/network and FFmpeg; native web export includes those browser processes and the progressive file sink's coordinator. Shared pages may be counted more than once and sampling can miss short peaks. These numbers are aggregate process RSS, not unique physical memory.

| Backend at 720p | 20 s peak MiB | 60 s peak MiB | Export seconds, 20 / 60 | Export factor, 20 / 60 |
| --- | ---: | ---: | ---: | ---: |
| Reference Chromium → FFmpeg VP9/Opus | 1433.32 | 1499.72 | 15.76 / 39.62 | 0.788 / 0.660 |
| Native WebCodecs → progressive host file | 1512.29 | 1675.63 | 20.20 / 64.43 | 1.010 / 1.074 |

Export factor is elapsed export time divided by movie duration. The native measurement includes the Playwright binding that carries encoded packets to the host sink; it is not a measurement of encoding alone or a browser-local download sink.

The 60-second project resets each cycle to the original first snapshot and repeats the PCM data three times under a new asset version/hash. All 1440 draw-command states match the original modulo 480 before export. Both Node outputs decode exactly 480/1440 VP9 frames and 960000/2880000 audio samples. Both native outputs decode those frame counts and 960648/2880648 audio samples, preserving the separately documented 648-sample Opus tail. The existing FFmpeg Opus EOF diagnostic is retained in every report; exit codes and complete decoded counts are checked. See `node-export.md` and `browser-export.md` for codec padding and the earlier source investigation.

Three times the frames increased measured peak aggregate RSS by 4.63% for Node and 10.80% for native web export. This supports the bounded-frame result for this workload alongside direct ownership/queue evidence: Node captures and awaits one frame/write at a time; native producer/video capacities are one, audio capacity is four, and observed native encoder queues were one each. Native live VideoFrame/AudioData/encoder sets all end at zero, and tracked closed objects are deleted from the audit sets. The host sink has one active write and never accumulates the complete compressed file in a Blob.

All 22 observed Node-export Chromium/FFmpeg PIDs and all 21 observed native-export Chromium PIDs were absent from the live process table afterward, including any reparented process. Preview aggregate RSS peaks across its three passes were 1721.81, 1660.97 and 1652.59 MiB, settling after the first pass. The preview coordinator also contains compiler/bundle benchmark allocations; this is not an isolated FxPlayer heap figure. A bounded frame queue does not imply constant memory for arbitrary-duration assets: decoded audio and input bytes scale with their source duration.

The public `ExportReport.peakRssBytes` still measures only its Node coordinator. The separate process traces provide the full pipeline observation. There is no universal heap-leak claim, forced-GC measurement, physical mobile result or Firefox/WebKit 60-second memory claim.
